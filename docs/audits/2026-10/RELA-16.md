# RELA-16 — Every advertised feature vs what the app does

Repository `screen-gd/relay` at HEAD `302d4445c52437d6c9bfdf42463720190384c9c8` ("Add a dark-mode
showcase video of the marketing site"). Audit only: no commits, no branches, no PRs, no source edits.
`git status --porcelain` is empty at HEAD 302d444.

**Model provenance.** Every row below was produced on `deepseek/deepseek-v4.1-flash` at high reasoning
in this thread. Two Claude subagents ran briefly before the crew's model rule reached me; their output
is not used and is not cited anywhere in this report. See Needs.

## Outcome

Relay's core promise holds. The workflow the README describes — clients, projects, workflow stages,
outputs and versions, review, files, earnings, salary contracts — exists, is navigable, and renders
real surfaces. I checked it at runtime, not just in source.

The expensive gaps are all in the same direction: **the product tells users about capabilities it
cannot give them, and the app's own commercial switchboard is wired to nothing.**

- Nothing can be bought. Every paid capability — Creator, Team, hosted uploads, Client Hub, portal
  branding, advanced reports — is gated behind a plan no user can obtain.
- The one knob the README documents for that (`NEXT_PUBLIC_BILLING_PURCHASES_ENABLED`) is read by no
  code in the repository. The knob that actually closes trials is a different variable.
- The AI surface exposes a consent control and a documented monthly quota, and no feature in the
  repository can start an AI run.
- Two claims that carry real user risk are wrong as written: "password-protected" review links (it is
  an optional PIN, off by default) and "short-lived signed links" for hosted files (the live Convex
  storage path returns URLs with no expiry).

### How I ran it, and the one deviation

```
cd /workspace/relay
pnpm install --frozen-lockfile          # clean, pnpm 10.11.1, node 24.18.0
cp .env.production .env.local
pnpm dev:next                           # next dev --port 3100
```

With `.env.production` copied verbatim, **the app never leaves "Loading Relay…"**. The committed
Clerk publishable key is a live key, and the browser console reports, twice:

```
Clerk: Production Keys are only allowed for domain "relay-app.cc.cd".
API Error: The Request HTTP Origin header must be equal to or a subdomain of the requesting URL.
```

Both public keys are set, so `Providers` picks cloud mode (`src/app/providers.tsx`: `hasCloudConfig =
hasConvexConfig && hasClerkConfig`) and the shell waits on Clerk forever
(`src/features/workspace/workspace-runtime.tsx:140`: `{!isAuthLoaded ? <AppLoadingStatus /> : null}`).
Screenshot: `renders/RELA-16/loading-relay-clerk-blocked.png`.

**Deviation I have to declare:** to reach Local Mode I blanked `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` in
`.env.local` (gitignored) and restarted. `.env.production`, `wrangler.jsonc` and every tracked file
are untouched. This is a real finding as well as a workaround — the documented local method does not
boot — so it is row 29 below rather than a silent footnote.

### Gaps, ranked by cost

1. **Nothing can be bought, so an entire advertised tier is dead.** Creator is unreachable, Team is
   unreachable, and everything gated on them — hosted uploads, Client Hub, custom portal branding,
   custom Workflow Templates, advanced reports, shared storage, Editor seats — is listed in the app,
   the site and the docs and can never be switched on. The app has no payment provider at all (no
   Stripe or Razorpay integration in `src/`, `convex/` or `website/`), the trial is closed by a
   deployment variable, the one documented switch is dead code, and the only billing surface
   (`/organization-profile`, Clerk's `UserProfile`) has no navigation entry and sits in
   `src/app/robots.ts:21`. A user who wants the paid product has no path and no waiting list — the
   `/waitlist` page 308-redirects away. Cost: the commercial model cannot ship, and every upsell
   button in the product leads to a page that says "not available yet".
2. **An AI consent control with no AI behind it.** `/settings` renders "AI assistance — Allow AI in
   this workspace. Owners and Editors trigger each run." The docs state a monthly allowance (10 Free /
   300 Creator runs, `docs/architecture/ai-foundation.md:11`). No feature in the repository calls
   `enqueueAiRun`, and `internal.aiRuns.claim` is called only from tests. Cost: an owner grants consent
   for a capability that does not exist, and reads a quota they cannot spend. This is a trust and
   provisioning problem, not a cosmetic one.
3. **"Password-protected" review links are not protected by default.** The site says
   "password-protected link" and "Client portals with password links"; the product ships an optional
   PIN with an unchecked toggle. Cost: the highest user-harm gap here — an editor believes a client's
   cut is protected, shares the URL, and anyone who has the link can watch it. The architecture doc
   already admits protection is optional; the marketing copy does not.
4. **"Short-lived signed links" for hosted files is not true on the live storage path.** The claim
   appears in the README and APP-OVERVIEW as a security property. Convex storage URLs are returned
   with no expiry; only the disabled R2 path signs 15-minute URLs. Cost: a security expectation the
   shipped path does not meet, in the same sentence as the file privacy promise.
5. **Sample Studio's navigation drops the visitor out of the sample into their own empty workspace.**
   Clicking any sidebar entry while in `/sample-studio` goes to the real route (`/projects` and
   friends) with zero records, and the Local Mode onboarding dialog reopens on top. The banner still
   says "Sample studio — Read-only production data". Two smaller problems sit with it: the sample data
   is never labelled fictional, which `docs/visibility.md:23` explicitly requires, and its money
   figures change between page loads (I recorded "Paid $1,192", "$1,197", "$1,198", "$1,200" across
   four loads of the same dashboard). Cost: this is the primary pre-signup demonstration, and it hands
   a prospect an empty product.
6. **The documented local method does not boot.** With `.env.production` copied as instructed, the app
   hangs at "Loading Relay…" because the committed Clerk key is a live production key restricted to
   `relay-app.cc.cd`. Getting to Local Mode — which the README presents as a headline way to use the
   product — requires removing a committed key. Cost: every developer and QA run starts with a
   workaround, and "Local Mode, work without an account" is unreachable exactly as documented.
7. **The domain vocabulary contradicts the UI on money.** README:67 makes Earned/Collected/Outstanding
   a stated consistency rule; the shipped report says Earned/Paid/Unpaid, and "Collected" and
   "Outstanding" appear nowhere in `src/` or `convex/`. Cost: the CSV invoice drafts, the reports and
   any document written from the README use different words for the same three numbers, which is the
   kind of drift that shows up later as a mis-stated total.
8. **The calendar promises a subscribeable feed and ships a download.** No `text/calendar` endpoint
   exists; both probed URLs 404. Cost: an editor who plans to subscribe their calendar gets one static
   file that never updates.
9. **"Workspace accounting supports multiple currencies" is false**, in the AI-facing summary and in
   the plan doc. One currency per workspace. Cost: an AI answering questions about Relay will state a
   capability that does not exist.
10. **Smaller but real:** `/access` is documented as a preserved route and 404s; the app calls itself a
    private beta while the site says no invite is required; the app and the site use two different
    support addresses; cards labelled "Connect" state in their own body that Relay does not connect;
    workspace search silently stops at 500 projects; a `cutlab-studio:` key survives the "clean
    rebuild"; `Storage Add-on` is a defined domain term behind a "remain disabled" comment.

## Lesson

The audit's second direction — what exists in code but no user can reach — turned out to be where the
money is, and it is invisible from the marketing copy alone. `grep`-ing for the documented switch
(`NEXT_PUBLIC_BILLING_PURCHASES_ENABLED`) across the whole tree and finding four hits, all of them
configuration files and none of them code, took one command and reframed the entire commercial story.
Next time on a claim audit, start by grepping every documented feature flag and env var for a real
reader; a flag with no reader is the cheapest high-value finding there is.
