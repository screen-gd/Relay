Set up Col MCP

Search Col’s libraries and verified components from your coding agent.

#Connect your client

#How Col answers

Col is read-only: it never touches your project, and never asks for an account, API key, or any credential. Its four tools search one curated catalogue — search_libraries, search_components, get_library, and get_component.

Every result is built to be checked, by the agent and by you:

  • A canonical source link on every record — always the library's own documentation.
  • Verification stated per part — page, install, compatibility, snapshot — so "verified" never means different things in different tools.
  • Gaps stay explicit. A missing component means "not yet verified", never "this library lacks it", and unverified compatibility stays unknown.
  • matchedOn says why a result matched: name, alias, tag, or description.
  • Empty results explain themselves (indexStatus) and suggest close matches instead of returning silence.
  • Documentation snapshots carry their fetch date and source revision, so anything quoted can be re-checked later.
  • When Col recorded a story, get_component also returns a preview: a themed URL and a screenshot showing the component in a use-case scene, with the rendered source, applied theme, and its own explicit gaps. A missing preview is itself a gap — never evidence about the library.

#Troubleshooting

  • No tools listed: check the URL, enable Col in your client, and start a new session after changing configuration.
  • Connection failed: select HTTP, not a local command or SSE. Check your client’s server logs and network access to the endpoint.
  • A browser visit returns a method error: the endpoint expects MCP POST requests. Confirm the connection through your client instead.
  • An empty search result: shorten the query or adjust filters, then check the library’s official docs. Coverage is partial.
